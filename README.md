# Clinic Flow

**Рабочее название.** Модуль управления потоком пациентов в региональных поликлиниках: подтверждение прибытия, электронная очередь, вызов, табло, маршрутизация и аналитика. Не заменяет МИС.

> Версия 0.3.0 (кандидат) — демонстрационный стенд на синтетических данных. С опциональным общим паролем персонала, без промышленной аутентификации, подключения к МИС, медицинской сортировки и реальных персональных данных. Не выставлять в интернет и не использовать для реального приёма.

## Что уже работает

- Терминал: выдача тестового талона, подтверждение предварительной записи (коды DEMO-101, DEMO-102, DEMO-103).
- Интерфейс врача: очередь кабинета, вызов, повторный вызов, начало/завершение, отметка неявки, отмена ожидающего талона, возврат неявки, перевод между кабинетами с сохранением истории.
- Табло коридора и отдельного кабинета: номер приглашённого талона, статус кабинета, индикатор связи, событийные обновления SSE и опциональная озвучка средствами браузера.
- Аналитика по этапам визита: медиана ожидания, длительность приёма, неявки и переводы.
- FastAPI, SQLite WAL или PostgreSQL, транзакции, журнал событий, OpenAPI и CI для обеих БД.
- Синтетические записи на конкретное время, защита повторной выдачи талона и от устаревших действий сотрудника.

Алгоритм демо — наступившие записи по времени слота, остальные FIFO; после 30 минут ожидания доступные талоны сортируются по прибытию. Будущие слоты не вызываются досрочно. Это **не медицинский алгоритм**. В реальной поликлинике правила записи и приоритета определяет учреждение. Талон не отменяется автоматически до назначенного времени. Приём без записи и неотложная помощь не должны блокироваться.

- Управление кабинетами в демо-интерфейсе врача, раздельные сервисы и репозитории, PostgreSQL/Alembic, Idempotency-Key для критических команд.

## Запуск

Требуется Python 3.13 или Docker Compose.

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements-dev.txt
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Альтернатива:

```bash
docker compose up --build -d
```

### Сценарий демонстрации

1. Открыть четыре вкладки: терминал, врач, табло, аналитика.
2. На терминале подтвердить `DEMO-101` или создать талон в кабинет 101. Запомнить номер.
3. На странице врача выбрать кабинет 101 и нажать «Вызвать следующего».
4. На табло появится номер талона (SSE; при отсутствии связи резервный опрос).
5. Врач начинает и завершает приём. Можно также повторить вызов, отметить неявку или отменить ожидающий талон.
6. Перенести пациента в кабинет 102, вызвать его там с тем же номером. Завершить приём и открыть аналитику.
7. В интерфейсе врача создать синтетическую запись `DEMO-TEST` с будущим временем. Проверить подтверждение прибытия и отсутствие досрочного вызова.

Для чистого демо запустите с новым путём БД: `CLINIC_DB_PATH=data/demo2.sqlite3 python -m uvicorn app.main:app --port 8000`. Тестовые коды одноразовые после завершения приёма. Не удаляйте рабочие данные без резервной копии.

### PostgreSQL (локальный стенд)

Укажите свой локальный пароль в переменной окружения или в непубликуемом файле .env: CLINIC_POSTGRES_PASSWORD. Затем:

```bash
docker compose -f compose.postgres.yaml up --build -d
```

Не запускайте оба Compose-варианта одновременно на одном порту. Схема создаётся Alembic. Для переноса старой SQLite-базы сначала создайте пустую PostgreSQL БД и выполните миграции без запуска приложения; см. [инструкцию v0.3](docs/13-release-v03.md).

## Обновление v0.1 → v0.2

Остановите приложение и сохраните резервную копию БД. При запуске схема мигрирует автоматически; существующие талоны сохраняются. Не возвращайтесь к старому коду без восстановления резервной копии.

Для ограниченного локального демо можно задать `CLINIC_STAFF_PASSWORD` в окружении (логин `staff`); не передавайте пароль в Git. HTTP Basic без TLS не годится для клинической сети. Для Docker переменная передаётся из `.env` или окружения.

## Разработка

```bash
python -m pytest -q
node --check app/static/app.js  # опционально, если установлен Node.js
python scripts/smoke_sse.py     # реальный локальный HTTP и SSE
# Опциональный браузерный сценарий (требует playwright и Chromium):
# python scripts/smoke_browser.py
```

`app/domain/` — правила; `app/services/` — транзакционные команды; `app/repositories/` — SQLite/PostgreSQL; `app/queue.py` — совместимый фасад; `app/main.py` — HTTP API; `app/static/` — интерфейсы; `migrations/` — Alembic; `tests/` — проверки. PostgreSQL-тесты требуют TEST_POSTGRES_URL на отдельную тестовую БД (в CI настроено).

История v0.2 — [отчёт](docs/11-release-v02.md). Текущий статус проверок — GitHub Actions для соответствующего коммита; ограничения v0.3 — [отчёт](docs/13-release-v03.md).

Лицензия проекта пока не выбрана. Исходники написаны для данного стенда; код сторонних очередей не копировался. Наличие приватного репозитория само по себе не определяет условия лицензирования.
