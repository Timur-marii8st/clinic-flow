# Развёртывание Linux kiosk (Orange Pi / Raspberry Pi / x86)

Кандидат на локальный демонстрационный стенд. Не заявляем совместимость с любой платой, дистрибутивом или монитором без проверки. Предпочтительно ARM64 Armbian/Debian или Raspberry Pi OS с графической сессией, Chromium, Python 3 и systemd. Врачебный ПК использует обычный браузер.

## Подготовка

1. Подключите HDMI, питание и Ethernet, настройте время/NTP, звук и разрешение. Установите Chromium и Python 3 средствами дистрибутива (имена пакетов отличаются; в Debian обычно chromium python3). Для загрузки без Интернета подготовьте пакеты и образ заранее.
2. Настройте отдельного непривилегированного пользователя и графическую сессию. Для автоматического старта после питания согласуйте автологин выделенного пользователя, отключение гашения экрана/DPMS в соответствующем X11/Wayland окружении. Не включайте root-автологин.
3. Для сетевого устройства подготовьте HTTPS secure-профиль Clinic Flow, доверенный сертификат и регистрацию устройства администратором. Не используйте незащищённый demo HTTP по LAN; HTTP разрешён launcher только на loopback. Не отключайте проверку TLS.

## Установка

Из клонированного репозитория под выделенным пользователем в графической сессии:

```bash
bash deploy/kiosk/install.sh
nano ~/.config/clinic-flow/kiosk.env
```

Например:

```ini
CF_KIOSK_URL=https://clinic.example/board?room=101
CF_AUTOPLAY=1
```

Для общего табло используйте /board без room, для терминала /kiosk. Для локального теста на том же ПК допустимо http://127.0.0.1:8000/board?room=101. CF_CHROMIUM позволяет указать путь к Chromium, CF_PROFILE — отдельный профиль. Не помещайте токены в URL/файл окружения. CF_AUTOPLAY=1 разрешает автоматическое локальное аудио только на выделенном профиле Chromium, не на обычном компьютере; проверьте политику браузера. Значение по умолчанию 0, тогда нужно нажать «Включить озвучку».

```bash
systemctl --user import-environment DISPLAY WAYLAND_DISPLAY XAUTHORITY
systemctl --user enable --now clinic-flow-kiosk.service
systemctl --user status clinic-flow-kiosk.service
journalctl --user -u clinic-flow-kiosk.service -f
```

Если desktop не запускает graphical-session.target, настройте автозапуск команды systemctl --user start clinic-flow-kiosk.service после появления графической сессии и импорта окружения. Не запускать одновременно два Chromium с одним profile. При первом запуске secure-устройство попадёт в /pair: создайте одноразовый код администратора, введите на устройстве. После регистрации перезапустите сервис для применения исходного room/device/audio URL, проверьте правильный scope и звук. Cookies сохраняются в выделенном профиле с правами 0700; доступ к OS и физическому устройству должен быть ограничен. По истечении срока устройства выпустить новый pairing code и отозвать старое устройство по регламенту.

## Сбой и приёмка

- systemd перезапускает supervisor; тот проверяет /health с TLS и повторно запускает Chromium при выходе процесса, а также после двух неудачных проверок и последующего восстановления связи. Интервал проверки около 5 секунд плюс время HTTP-запроса. Renderer hang не определяется достоверно. Во время сетевого сбоя сам интерфейс показывает offline/stale; при старте без сервера supervisor ожидает доступность. Согласуйте ручной резервный процесс.
- Проверить: загрузка после подачи питания, корректное разрешение/масштаб, клавиатурный USB-сканер с Enter и английской раскладкой (CF1 чувствителен к регистру), вывод аудио, recovery при отключении Ethernet, удаление старого вызова и отсутствие повторной озвучки после reconnect, online/stale/unknown в админке, отзыв устройства.
- На реальной плате отдельно проверить часы, доступность, энергопотребление, температуру, стабильность Chromium/SD/SSD, 48–72 часа непрерывной работы и поведение после отключения питания. Зафиксировать модель платы, дистрибутив/ядро, браузер, монитор, сканер, аудиоустройство, результат и ответственного. Пройти согласование с ИТ/ИБ перед сетевым подключением.
- Остановить: systemctl --user disable --now clinic-flow-kiosk.service. Не удалять профиль до отзыва устройства в админке. Секреты, реальные данные и пароли в Git не добавлять.
