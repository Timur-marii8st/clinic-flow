# 5. Информационная безопасность и приватность

## Ограничения текущего стенда

Есть опциональный общий HTTP Basic пароль для персонала (по умолчанию выключен). Нет индивидуального входа, RBAC, TLS, аутентификации устройств, реального аудита операторов, резервного контура или проверки безопасности зависимостей. Без настройки пароля любой человек с доступом к порту может управлять очередью. С паролем общедоступные операции терминала всё ещё не имеют аутентификации устройства. POST принимает только JSON; cross-origin запросы браузера отклоняются. Запуск только на localhost, только синтетические данные. Не менять bind на 0.0.0.0 для доступа из клинической сети до согласованного hardening. Docker публикует порт только на loopback.

Номера талонов не являются гарантией обезличивания: сопоставление с расписанием может восстановить личность. Не показывать ФИО, диагноз, номер полиса и прочие идентификаторы публично.

## Угрозы и обязательные меры перед пилотом

| Угроза | Мера |
|---|---|
| Посторонний управляет вызовом | SSO/учётные записи, роли по учреждению и кабинету, least privilege |
| Подмена табло или терминала | Учет устройства, отдельная роль read-only, TLS, разрешённые адреса и сегменты |
| Двойной/повторный вызов | Транзакции, уникальность активного талона, idempotency key, optimistic version |
| Утечки через логи/экран | Минимизация полей, запрет секретов и ПД в логах, ограничение доступа |
| Устаревшие вызовы | Heartbeat, срок актуальности, явный offline-режим |
| Сбой сервера или сети | Согласованный ручной процесс, резервирование/backup/restore, мониторинг |
| Уязвимость зависимостей | Версионирование, SCA/SBOM, проверка обновлений, минимальный образ, патчинг |
| Нарушение прав пациента | Приоритеты и исключения только по согласованным правилам, ручное вмешательство медработника |

До пилота с реальными данными: определить оператора ПД и правовые основания, модель угроз, границы системы, порядок обработки и хранения; согласовать требования с ИТ и ИБ учреждения. Ориентиры для профильной проверки: 152-ФЗ, 323-ФЗ (врачебная тайна), применимые требования к ИСПДн и ГИС. Это не заключение о соответствии; актуальные редакции и применимость должны быть проверены специалистами для конкретного внедрения. Не предполагать автоматически наличие или отсутствие требований к медицинским изделиям или КИИ.

Критерий допуска: роли и аудит проверены, интеграция и документация согласованы, восстановление отработано, публичные проекции и логи прошли проверку, у персонала есть безопасный ручной режим. До этого — только демонстрационный контур.
