# 11. Release v0.2 — что проверено

## Функции

- Визит/этап: один номер талона при переносе между кабинетами, история этапов, транзакционный переход.
- Синтетический импорт записи, слот, недосрочный вызов, FIFO/aging; без автоматической медицинской сортировки.
- Возврат неявок, уникальный ключ выдачи, конфликт устаревшей версии, SQLite WAL и миграция v0.1.
- SSE: постоянное соединение, уведомление после транзакции, heartbeat 10 секунд, snapshot при reconnect, fallback polling 2 секунды.
- Аналитика: число ожидающих, завершения, неявки, переводы, медиана ожидания и приёма по последним 100 закрытым этапам. Медиана длительности приёма выводится от 3 наблюдений. Это не ETA.
- Опциональная озвучка через Web Speech API, без гарантии наличия русского локального голоса. Опциональный HTTP Basic пароль персонала; не production IAM.

## Проверки в среде подготовки

| Проверка | Результат |
|---|---|
| `python -m pytest -q` | 14 тестов пройдено |
| `node --check app/static/app.js` | Синтаксис JS корректен |
| `python scripts/smoke_sse.py` | Реальный Uvicorn, 2 HTTP SSE-подписчика, получение snapshot и переподключение прошли |
| Одиночный локальный прогон вызов→уведомления→чтение табло | 8,5 мс в одном измерении; не нагрузочный тест, не измерение отображения в браузере |
| `python scripts/smoke_browser.py` | Подготовлен сценарий Playwright; в среде исполнения Chromium заблокировал loopback (ERR_BLOCKED_BY_ADMINISTRATOR), e2e не подтверждён |
| Docker/CI | Конфигурации есть; Docker отсутствовал, на момент подготовки архива удалённый CI не запускался |

При простое один экран с SSE и heartbeat раз в 10 сек делает около 6 snapshot GET/мин вместо 30 при polling 2 сек (на 80% меньше периодических GET, без учёта открытия потока и действий). При активной очереди число запросов зависит от частоты событий. Не измерялись реальные CPU/RAM, скорость Orange Pi, многопользовательская нагрузка или задержки клинической сети.

## Критические ограничения

Демо на синтетических данных, только loopback. Реальной интеграции с МИС нет. Нужны индивидуальная IAM/RBAC, TLS, устройство/кабинет/учреждение в модели доступа, аудит операторов, политика хранения, резервное копирование, проверка зависимостей и согласование медицинских правил. Возможности управления без авторизации по умолчанию оставлены только для локального стенда. Событийный сигнал находится в памяти одного процесса; перезапуск/переподключение получает новый snapshot. Для пилота проверить нагрузку, брокер/общий outbox по необходимости, резервный ручной процесс. Проектная лицензия ещё не выбрана.

## Публикация

Версия v0.2 импортирована в [репозиторий Clinic Flow](https://github.com/Timur-marii8st/clinic-flow) в ветку main. Исходный архив сохраняет отдельную локальную историю двух коммитов; на GitHub создана новая история импорта через GitHub API без force push. Для дальнейшей разработки клонировать опубликованный репозиторий:

```bash
git clone https://github.com/Timur-marii8st/clinic-flow.git
cd clinic-flow
docker compose up --build -d
```

Статус автоматических проверок опубликованной версии смотреть в GitHub Actions. Репозиторий публичный; не включать в него секреты, личные контакты и данные пациентов.
