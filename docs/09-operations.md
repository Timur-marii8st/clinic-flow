# 9. Эксплуатация и тесты

## Локальная разработка

Команды в README. База по умолчанию `data/clinic.sqlite3`, конфигурация переменной `CLINIC_DB_PATH`. `.env.example` — пример; при запуске Python загрузку `.env` автоматически не выполняем. Для Docker путь задан в Dockerfile и данные на named volume. `docker compose down` сохраняет том; `docker compose down -v` уничтожает том и демо-данные.

## Проверки

`python -m pytest -q`: сквозной HTTP-сценарий, повторный check-in, неверные действия, изоляция кабинетов, неявка/отмена, конкурентный вызов, сохранение после повторной инициализации, маршруты UI. 14 тестов, включая миграцию v0.1, историю этапов, повторы, конфликт версии, слоты и опциональный пароль. `python scripts/smoke_sse.py` проверяет реальное HTTP-соединение с двумя подписчиками и переподключение. Проверить дополнительно руками на трёх вкладках и на реальном SBC. Конфигурация GitHub Actions присутствует, но не запускалась удалённо на момент подготовки архива. Docker-сборка не проверена (Docker отсутствует в среде). Браузерный smoke-скрипт подготовлен, но среда заблокировала переход на loopback в Chromium; проверить на обычном рабочем ПК.

## До пилота

Интеграционные тесты с МИС, правила расписания, миграции, авторизация, идемпотентность, аудит, резервное копирование с контрольным восстановлением. Нагрузочный тест по числу экранов/кабинетов, измерение времени ответа и числа запросов. Ранее polling 2 сек давал 30 GET/мин на табло при простое; SSE с heartbeat 10 сек даёт около 6 snapshot GET/мин на табло при простое плюс один постоянный поток и обновления после мутаций. Это расчёт, не нагрузочный бенчмарк. Проверить число устройств, proxy buffering, задержку сети, CPU/RAM и реконнекты. Не хранить реальные данные в демо-базе.

При сбое экран скрывает данные и показывает сообщение. Если сервер недоступен, персонал действует по штатному регламенту, а не ждёт восстановления. В пилоте нужны healthchecks, мониторинг задержек и устройств, алерты, журнал инцидентов, контроль версий. Согласовать план обновления и отката, RPO/RTO и SLA до запуска; проверить восстановление из резервной копии.
