# 7. Проверка гипотез, пилот и бизнес

## Customer discovery

Нужны контакты разработчика МИС и сотрудников клиники: заведующий отделением, старшая медсестра/регистратор, ИТ-специалист и владелец бюджета. Не включать личные контакты в репозиторий.

Три первоначальных вопроса: как сейчас приглашают пациентов, какие конкретные причины задержек и есть ли замеры, какие функции очереди уже есть в МИС и какие отсутствуют. Попросить показать последний реальный случай, а не оценивать понравилась ли идея. Уточнить порядок допуска сторонней системы, кто платит и кто отвечает за оборудование. Наблюдение не должно включать копирование ПД или медицинских записей.

## Дизайн пилота

- Выбрать один поток (три кабинета одного участка или ограниченный маршрут диспансеризации) с повторяемой проблемой; сравнивать сопоставимые смены и нагрузку.
- До внедрения собрать baseline. После согласования инфраструктуры проводить пилот под ответственностью учреждения; доступный ручной процесс обязателен.
- Использовать агрегаты и обезличенные протоколы наблюдения. Не проводить эксперимент с медицинскими приоритетами.
- Предлагаемые стартовые ориентиры (не гарантия и не доказанный эффект): снижение медианного ожидания на 15%, снижение ручных вызовов на 50%, доступность стенда 99.5% в часы работы. Уточнить пороги после baseline; p90 ожидания и доступность для пришедших без записи не должны ухудшаться.

| Метрика | Формула / измерение |
|---|---|
| Ожидание | начало приёма − подтверждённое прибытие; p50 и p90, по типу записи |
| Отклонение от записи | начало приёма − назначенное время, отдельно для опоздавших |
| Пауза между визитами | следующий старт − предыдущий конец; исключить обед и плановые паузы |
| Неявка | подтверждённые по регламенту неявки / записи; не путать с отсутствием check-in |
| Ручные вызовы | количество выходов врача / число посещений |
| Полный маршрут | время окончания последнего этапа − прибытие |
| Сбой | недоступное время / согласованные часы эксплуатации |
| Доступность | обращения за помощью, неуспешные регистрации, доступ без смартфона |

## Коммерческая гипотеза

Возможные модели: внедрение и поддержка штатной очереди, собственный модуль (лицензия/сопровождение), OEM-партнёрство с поставщиком МИС. Заказчик может быть клиника, региональный оператор или вендор — не подтверждено. Выяснить реальный закупочный путь, бюджет, SLA, объём интеграции, стоимость владения и ответственных. Не считать пилот продажей без договорённости о деньгах.

Минимальная экономика: стоимость устройства + установка + замена + поддержка + интеграция + работа команды + налоги/накладные. Не обещать экономию из одних только минут ожидания; показать, кому достаётся ценность. Stop-критерий: существующая функция закрывает проблему настройкой, нет доступного интерфейса и партнёра либо клиника не видит измеримого эффекта.
